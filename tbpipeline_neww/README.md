# tbpipeline_neww

A Win16 sandbox around TB80.

Every unpacked NE file in `--b` is loaded into one address space. A fixup inside `TB80RTM` that names `TB80W16` is written as that DLL's selector and offset, so the call is a real far call. `KERNEL`, `USER`, and the other system modules are not files. They are gates. The guest calls the gate, the sandbox answers, and the gate's `retf` pops the arguments.

An ordinal with no contract stops the run. The pop size is not guessed. The stop reads `unimplemented KERNEL.N: no contract, pop size not guessed`.

```
python3 -m tbpipeline_neww --b ~/TBK/bin
```

Needs `unicorn` (`pip install -r requirements.txt`) for a run. `--help`, and a missing `--b`, print the usage without it. This is not `tbpipeline_bf`. That tree answers each crash and keeps going. This one links the modules first, and Windows is only the calls that have a contract.

## Record

- When `TB80BAS` is in `--b`, startup prints one line: its exports stay in the DLL. The sandbox has no Python `CDB*`, `OBJ*`, `HEAP*`, `STACK*`, or `RESMGR*`. `tests/test_neww_bas_stays.py` holds both.
- A gate with no contract stops on its `OUT`. Its stub has no `retf`, so nothing is popped, and the sandbox writes neither `AX` nor `DX`. `tests/test_neww_gate_no_pop.py` sets `AX`, calls an unknown ordinal, and checks `SP` holds only the far return.
- A contract is a `Contract` row in `wine.py`: module, ordinal, name, argument sizes in bytes, return. The gate's `retf` pops `sum(args)`, and nothing else sets the pop. `tests/test_neww_contract_row.py`.
- Every `KERNEL` and `USER` row is built by `Contract.from_spec()` from the Wine line it cites: `dlls/krnl386.exe16/krnl386.exe16.spec` or `dlls/user.exe16/user.exe16.spec`, Wine commit `2528aff2`, by ordinal. The argument sizes come from the spec's types (`word`, `s_word` 2; `long`, `ptr`, `str`, `segptr`, `segstr` 4), not from pushes in the ToolBook binary. A row may record a `binary` pop size. If it differs from the spec, the row is not used: the gate stops and the message names both sizes. `tests/test_neww_wine_spec.py`; set `WINE_SRC` to a Wine checkout to compare every line with the file.
- The `__WINFLAGS` equate is not from Wine. Wine's `krnl386.exe16.spec:178` says `0x413`. neww keeps `0x0C25`, the value `bf` and `newl` use.
- `KERNEL.3` `GetVersion` is answered by its row alone: `value = (0x0A03, 0)`, Windows 3.10 in `AX`, `DX` 0, the same pair `newl` returns. There is no `GetVersion` branch in `_kernel`. `tests/test_neww_getversion.py`.
- `KERNEL.132` `GetWinFlags` is answered by its row alone: `value = (0x0C25, 0)`, the same word as the `__WINFLAGS` equate. `tests/test_neww_getwinflags.py`.
- `KERNEL.91` `InitTask` stops by name. It used to return `AX = 1` and nothing else. Wine's `InitTask16` (`dlls/krnl386.exe16/task.c`) also sets `CX`, `DX`, `SI`, `DI`, and `ES:BX`, which points at the command line in the PSP, and it pushes one zero word. neww has no PSP, so the gate stops and names the registers. Any stop now leaves the guest's registers as they were. `tests/test_neww_inittask.py`.
- Gate arguments come from the guest's memory. `Machine.word` and `Machine.string` used to read the loaded image, so a pushed argument read as whatever the file had at that offset, usually 0. `tests/test_neww_args_live.py`.
- `KERNEL.30` `WaitEvent` follows Wine's `WaitEvent16` (`task.c`). `hTask` 0 is the current task, a posted event is taken, and the call returns 0. The single starting event is the one `ne_module.c` `NE_CreateThread` posts. A second wait would block, so it stops. A nonzero `hTask` stops too, because neww has no task handle to match. `tests/test_neww_waitevent.py`.
- `KERNEL.15` `GlobalAlloc(flags, size)` reads `size` as the whole dword: `arg(0) | arg(1) << 16`, with `flags` in `arg(2)`. Before, it took `flags` as the size and kept a Python bytearray that the guest could not reach. Now it follows Wine `global.c`: the size is rounded up to 32 bytes, and the block is mapped behind consecutive data selectors 64K apart, so selector + `__AHINCR` is the next 64K. The handle is the selector, or selector − 1 with `GMEM_MOVEABLE`. Size 0 (Wine's discarded block) and anything over 1M (page-granular selectors) stop by name. `tests/test_neww_globalalloc.py`.
- `KERNEL.74` `OpenFile` has a file table. Handles start at 5, because DOS keeps 0–4. A path ending in `.tbk` or `.sbk` opens the book from `--c`, whatever its directory. Any other path is looked up by base name, without case, in `--b`, and nowhere else. A path that is not found returns `HFILE_ERROR` (`0xFFFF`) with `nErrCode` 2 in the OFSTRUCT. That is Wine `OpenFile16`'s answer for a missing file, and it is chosen for that reason, not copied from `bf`. A `.tbk` without `--c` is a missing file too. Any mode other than read stops by name. `_lopen`, `_lread`, `_llseek`, and `_lclose` use the same table, and the arguments are read in Pascal order. `tests/test_neww_openfile.py`.
- Linking two ToolBook modules is tested on original fixtures. A fixup by ordinal or by name into another NE file becomes that export's selector and offset, and the far call runs the other file's code with no gate. An additive fixup (flag 4) is one location whose word is an addend. It used to be followed as a chain link, which wrote the target into whatever word the addend pointed at. `tests/test_neww_link.py`.
- A ToolBook fixup with no target, because the DLL is not in `--b` or the export is not there, is never a gate. It is linked to a trap. When the guest calls it, the run stops with `not linked: TB80RTM -> TB80W16.7`. Wine is not asked. Before, the fixup was left unwritten and the call died as an anonymous CPU exception. `tests/test_neww_toolbook_not_gate.py`.
- A run that ends without a stop has hit a cap, and now says so: `instruction cap 1,000,000 at CS:IP with no gate call pending, after N calls`, or the 15 second cap. It used to say `returned`, but there is no address to return to. The cap values did not change. `tests/test_neww_full_run.py` also holds the `TBK_BIN` run, which skips without it and asserts the stop is a named one.
- A stop that is a fault or a cap names where it happened: `CS:IP`, the module and segment, and the nearest export at or below `IP` from that module's entry and name tables, such as `at 0x20:0x6 in TB80BAS segment 2 +0x6, BASFAULT+0x2 (ordinal 3)`. The export is named, not reimplemented. `tests/test_neww_bas_fault.py`.
- neww does not draw a page. No module names `render.html` or the reader's `runtime.debug`, and a run writes no HTML. `tests/test_neww_no_render.py`.
- A segment with the iterated flag (bit 3) is not run. neww does not expand iterated or OPTLOADER segments, so it loaded them as zeros, and the shipped `TB80RTM.EXE` (138 of 139 segments packed) ran empty memory from segment 2 `+0x35A` to the instruction cap at `0x178:0x862A`. Now the run stops before the CPU starts: `packed image TB80RTM.EXE: 138 of 139 segments have the iterated flag, first is segment 2. neww does not unpack. --b must hold the unpacked images`. The executable is checked first. `tests/test_neww_packed.py`.
- The task starts the way Wine `ne_module.c` `NE_StartTask` starts one: `AX` 0, `BX` the NE stack size, `CX` the NE heap size, `SI` 0 (no previous instance), `DI` the instance handle (DGROUP's selector, or selector − 1 when DGROUP is moveable, as `GlobalAlloc` does), `BP` 0, `ES` the PSP, `DS` and `SS` DGROUP. It used to start with all of those 0 and no PSP. The PSP is Wine's `PDB16` (`include/wine/winbase16.h`) filled as `task.c` `TASK_Create` fills it: `int 20h` at 0, twenty `0xFF` file handles at `0x18`, `nbFiles` 20, `fileHandlesPtr` = PSP:`0x18`, and the command line at `0x80`, which is the base name of the `--c` book, or empty. Wine also fills the dispatcher at `0x05` and the environment at `0x2C`. neww has neither, so a read of either stops by name. `tests/test_neww_task_entry.py`.
- `KERNEL.91` `InitTask` is Wine's register contract (`dlls/krnl386.exe16/task.c` `InitTask16`), taken in Wine's order. When `CX` (the heap size `NE_StartTask` passed) is not 0, Wine calls `LocalInit16` first. neww has no local heap, so the run stops: `KERNEL.91 InitTask calls LocalInit16(DS=0x5c0, 0, CX=0x1000) first ... KERNEL.4 LocalInit has no contract`. That is the stop the shipped `TB80RTM` reaches. Next, Wine runs each loaded DLL's LibMain (`ne_segment.c` `NE_InitializeDLLs`). neww does not, so a ToolBook DLL with init code stops the run by name. With neither, neww writes INSTANCEDATA (`stacktop` `0x0A`, `stackmin` and `stackbottom` `0x0C`/`0x0E`, where `stackmin` is the caller's `SP` past the return address and `stacktop` is `stackmin − BX + 150`) and answers `AX` 1, `BX` `0x80` or past leading blanks in the PSP command line, `CX` the stack top, `DX` 1 (`SW_SHOWNORMAL`, the `cmdShow` of `TASK_Create`), `SI` 0, `DI` the instance, `ES` the PSP, with one zero word pushed under the return address. A stop writes none of it. `tests/test_neww_inittask.py`.
- `SP` at entry follows Wine `ne_module.c` `NE_StartTask`: the NE header's `SS:SP` offset, or, when it is 0, the stack segment's minsize plus the NE stack size, made even. DGROUP is minsize + stack + heap, so the stack is below the local heap. It used to start at the end of DGROUP, `0xAA4E` on `TB80RTM` instead of `0x9A50` (minsize `0x4250` + stack `0x5800`), inside the heap that `LocalInit16` puts at the end of the segment. A stack top outside DGROUP stops before the CPU runs. Wine also keeps a `STACK16FRAME` for its relay just below that top. neww has no relay, so nothing is reserved there. `tests/test_neww_stack_top.py`.
- `KERNEL.4` `LocalInit` is Wine `dlls/krnl386.exe16/local.c` `LocalInit16`, from `krnl386.exe16.spec` `4 pascal -ret16 LocalInit(word word word)`, pop 6. It writes Wine's initial heap into the guest: a fixed first arena, the heap info arena with `LOCALHEAPINFO` (`items` 4, `first`, `last`, `hdelta` `0x20`, `extra` `0x200`, `minsize`, magic `0x484C`), one large free block, and a last arena, all 4-byte aligned, then sets `INSTANCEDATA.heap`. Selector 0 is `DS`. Start 0 puts the heap at the end of the segment, sized by `GlobalSize16`. The result is in `AX` and in `CX`, as Wine sets it. Too little room returns 0 and writes nothing. `InitTask` now calls it with `CX` instead of stopping. DGROUP's block is rounded up to 32 bytes, as `GLOBAL_Alloc` rounds it, because that is the size `LocalInit16` reads. On `TB80RTM` that is `0xAA60`. `tests/test_neww_localinit.py`, `tests/test_neww_inittask.py`.
- A segment register that a contract sets is loaded by the guest. Unicorn's register write for `ES` or `DS` in 16-bit mode changes the selector but keeps the old descriptor base, so after `InitTask` set `ES` to the PSP, `ES:[0]` read 0 instead of `int 20h`. A register contract's stub (`ret` `register` in the spec) now jumps to a tail in the gate segment: `mov es, cs:[slot]`, `mov ds, cs:[slot+2]`, `retf pop`. Before the stub returns, the gate writes the two words: the contract's `ES` and `DS`, or the guest's own when the contract leaves them alone. Other stubs are unchanged. `tests/test_neww_segment_load.py`.
- `InitTask` runs the DLL entry points, as Wine `ne_segment.c` `NE_InitializeDLLs` does, instead of stopping. The order is Wine's: each DLL the executable loads, the DLLs it loads first, and only libraries with an entry point (`NE_InitDLL`). On `TB80RTM` that is `TB80RCR, TB80W16, TB80UTL, TB80LNL, TB80OLE, TB80FLT, TB80BAS`. Each `LibMain` gets `NE_GetDLLInitParams`' registers: `CX` the DLL's NE heap, `DI` its instance (DGROUP's selector, or − 1 when moveable), `DS` and `ES` its DGROUP, `AX BX DX SI` 0. `BP` points at the caller's `BP`, pushed, where Wine points it at the saved `BP` in its relay frame. A DLL's DGROUP gets its NE heap added, rounded to 32 bytes (`NE_CreateSegment`, `GLOBAL_Alloc`). The calls run from a trampoline that the InitTask gate returns to. Its `OUT 0xE6` answers InitTask, and then the guest pops `ES` (the PSP) and the caller's `DS` and returns with the zero word pushed. A DLL without a SINGLEDATA DGROUP stops by name, because Wine would pass a module handle and neww has none. Wine's `NE_CallUserSignalProc(USIG16_DLL_LOAD)` goes to its builtin USER and the guest does not see it, so neww has nothing for it. On `TB80RTM` the first `LibMain` (`TB80RCR`) calls `LocalInit`, `GetVersion`, and `DOS3Call`, then stops on `unimplemented WIN87EM.1`. `tests/test_neww_dll_init.py`.
- A register contract's gate keeps the guest's `DX` unless the contract sets it. The ordinary stub loads the ordinal into `DX` before `OUT 0E4h`. That is fine when the answer comes back in `DX:AX`, but a `-register` entry reads and sets registers, and `DOS3Call` came back with `DX` = 0. A register stub is now `OUT 0E7h` then `jmp` to its tail. The gate takes the ordinal from the stub's offset, `IP / 8`, and writes `DX` only when the contract names it, as `InitTask` does with `nCmdShow`. `tests/test_neww_register_dx.py`.
- `WIN87EM.1` `__fpMath` is Wine `dlls/win87em.dll16/win87em.c`, from `win87em.dll16.spec` `1 pascal -register __fpMath()`, pop 0, chosen by `BX`. 0, 1, and 2 are `WIN87_Init`: `fninit`, control word `0x1332 & ~0xC3` = `0x1330` (`CtrlWord_1` keeps `0x1332`), `fclex`, and `AX` 0. 4 sets the control word, 5 returns `CtrlWord_1`, 9 clears status, 10 returns 0, 11 returns installed (`AX` 1, `DX` 0), and 3 and 12 change nothing. Wine runs `fninit`, `fldcw`, and `fclex` on the host x87. The guest's x87 is Unicorn's, so they become `FPCW`, `FPSW`, and `FPTAG` writes. 6, 7, and 8 need Wine's host x87 (`frndint`, `fistp`, `fstsw`), so they stop by name, as any other `BX` does. `TB80RCR`'s `LibMain` calls it with `BX` 0. `tests/test_neww_fpmath.py`.
- `KERNEL.131` `GetDOSEnvironment` is Wine `task.c` `GetDOSEnvironment16` (`krnl386.exe16.spec` `131 pascal GetDOSEnvironment()`, pop 0, long). The block is fixed and made with the PSP, as `TASK_Create` makes it, and its selector is at PSP:`0x2C`, so reading that field no longer stops. Wine copies the host's environment strings into it. neww copies none, so the list is empty: a single 0, then `WORD 1` and `C:\WINDOWS\SYSTEM\KRNL386.EXE`. The answer is the SEGPTR in `DX:AX` (selector, 0). `tests/test_neww_dos_environment.py`.
- `KERNEL.23` `LockSegment` is Wine `global.c` `LockSegment16` (`23 pascal -ret16 LockSegment(word)`, pop 2). A handle of `-1` means the current `DS`. A handle with no block returns 0, as Wine's `VALID_HANDLE` check does. Otherwise the block's `lockCount` goes up and the handle is returned. A handle is a selector, or selector − 1 when moveable, the same numbering `GlobalAlloc` uses. `TB80RCR`'s `LibMain` calls `LockSegment(-1)`. `tests/test_neww_locksegment.py`.
- `KERNEL.5` `LocalAlloc` is Wine `local.c` `LocalAlloc16` (`5 pascal -ret16 LocalAlloc(word word)`, pop 4) in `CURRENT_DS`, on the heap `LocalInit16` built. `local.py` ports the arena code it uses: `LOCAL_GetHeap`, `LOCAL_FindFreeBlock`, `LOCAL_GetBlock`, `LOCAL_ShrinkArena`, `LOCAL_AddBlock`, `LOCAL_RemoveBlock`, `LOCAL_MakeBlockFree`, `LOCAL_RemoveFreeBlock`, `LOCAL_FreeArena`, `LOCAL_NewHTable`, and `LOCAL_GetNewHandleEntry`. Sizes 1 to 4 become 5. A fixed block is the first free arena that fits. A moveable block is prefixed by its handle and gets an entry in a handle table of `hdelta` entries. `LMEM_ZEROINIT` clears the block. The handle is also in `CX`, as Wine sets it. When no free block fits, `LOCAL_Compact` moves unlocked moveable blocks down and discards discardable ones, then `LOCAL_GrowHeap` reallocates the segment to 64K (see below). A moveable block already taken is freed first, as Wine frees it when no handle comes. The class is `LocalHeap`: it is KERNEL's local heap, not a `TB80BAS` `HEAP*` export. `tests/test_neww_localalloc.py`.
- `KERNEL.24` `UnlockSegment` is Wine `global.c` `UnlockSegment16` (`24 pascal -ret16 UnlockSegment(word)`, pop 2). A handle of `-1` means `DS`, and a valid block's `lockCount` goes down. The function is void, so `AX` is left as the guest had it. Wine's own FIXME, that it should return the lock count in `CX`, is not acted on. `tests/test_neww_locksegment.py`.
- `USER.118` `RegisterWindowMessage` (`user.exe16.spec` `118 pascal -ret16 RegisterWindowMessage(str) RegisterWindowMessageA`, pop 4) returns a string atom, the same one for the same name compared without case, from `0xC000` up. Wine adds the name to its session's global atom table, so Wine's number depends on what that session registered first. neww's table starts empty, so the first name is `0xC000`. That number is neww's, not Wine's. An empty name, or one longer than 255 characters, is not an atom and returns 0. `TB80RCR`'s `HELPINIT` registers `asymhelp_#p$y^r$z^q#x@g*l@`. `tests/test_neww_register_window_message.py`.
- `USER.291` `SetWindowsHookEx` is Wine `user.exe16/hook.c` `SetWindowsHookEx16` (`291 pascal SetWindowsHookEx(s_word segptr word word)`, pop 10, long). An id outside `WH_MSGFILTER` (−1) to `WH_SHELL` (10) returns 0. So does an id with no `hook_procs` entry (journal, sysmsgfilter, hardware, debug) and a second hook of the same id. A nonzero `hTask` is compared with `GetCurrentTask` in Wine. neww has no task handle, so that stops by name. The proc is kept, but neww has no message loop yet, so nothing calls it. Wine's HHOOK comes from user32. neww numbers its own from `0x00010001` in `DX:AX`. `TB80RCR`'s `ASYMMTRKINIT` sets `WH_MOUSE` with `hTask` 0. `tests/test_neww_setwindowshookex.py`.
- `KERNEL.49` `GetModuleFileName` is Wine `ne_module.c` `GetModuleFileName16` (`49 pascal -ret16 GetModuleFileName(word ptr s_word)`, pop 8). `hModule` 0 is the current task's module, the executable. Any handle of a module's block finds that module, as `GetExePtr` does. A handle that finds none returns 0. The path is copied with `lstrcpynA` semantics (at most size − 1 characters, then a 0), and its length is returned. Wine shows the module's host path through a DOS drive, shortened by `GetShortPathNameA` for pre-4.0 modules. neww's guest path for `--b` is `C:\TBK`, with the upper-case file name. Any directory works, because `resolve()` opens by base name. A name that is not 8.3 stops. `tests/test_neww_getmodulefilename.py`.
- `KERNEL.47` `GetModuleHandle` is Wine `ne_module.c` `WIN16_GetModuleHandle` (`47 pascal GetModuleHandle(segstr) WIN16_GetModuleHandle`, pop 4, long). A selector of 0 is a handle, given to `GetExePtr`. A name is matched as `GetModuleHandle16` does: by module name without case, then by the base name of the loaded file. `DX` is `hFirstModule`. Each NE file gets a module handle in Wine's load order, the executable and then each DLL as loaded, and the last one loaded is `hFirstModule`, as `NE_RegisterModule` puts each at the head. The handle is a 0x60 block with nothing in it. Wine fills it with `build_module`'s `NE_MODULE`, so a guest read of it stops. The list holds only neww's modules. A system module name (`USER`, `USER.EXE`) stops, because Wine's answer is its builtin and neww's system modules are gates. `tests/test_neww_getmodulehandle.py`.
- `USER.179` `GetSystemMetrics` is Wine `user.exe16/user.c` `GetSystemMetrics16` (`179 pascal -ret16 GetSystemMetrics(s_word) GetSystemMetrics16`, pop 2), which passes the index to `win32u/sysparams.c` `get_system_metrics`. The cases of that switch that return a constant are answered: `SM_CXBORDER`/`SM_CYBORDER` 1, `SM_CXDLGFRAME`/`SM_CYDLGFRAME` 3, `SM_MOUSEPRESENT` 1, `SM_CMOUSEBUTTONS` 3, `SM_CMETRICS` 90, and the rest. The cases that read the registry, fonts, or display stop by index. An index that is not a case returns 0, the switch's default. `TB80RTM` asks `SM_CXDLGFRAME` first, then `SM_CXSCREEN`, which stops. `tests/test_neww_getsystemmetrics.py`.
- `GetSystemMetrics` `SM_CXSCREEN` and `SM_CYSCREEN` are 1024 and 768. Wine answers them from the primary monitor. neww has no display driver. When the driver does not implement `UpdateDisplayDevices`, `win32u/sysparams.c` `update_display_devices` calls `default_update_display_devices`, which uses `modes[2]`, 1024×768, if no current mode is saved in the registry. neww has no registry, so it is that mode. `tests/test_neww_screen_size.py`.
- `GetSystemMetrics` `SM_CXFRAME` and `SM_CYFRAME` are 4. `win32u/sysparams.c` returns `SM_CXDLGFRAME` (3) plus max(`BorderWidth`, 1). `BorderWidth` is `TWIPS_ENTRY( BORDER, -15, ... )`, and `get_twips_entry` converts −15 twips to `muldiv(15, dpi, 1440)` pixels. A Win16 task is DPI unaware, so `get_system_dpi` is `USER_DEFAULT_SCREEN_DPI`, 96, and the border is 1 pixel. `tests/test_neww_frame_size.py`.
- `GetSystemMetrics` `SM_CYCAPTION` is 19. `win32u/sysparams.c` returns `iCaptionHeight` + 1. `iCaptionHeight` is the `CaptionHeight` default, −270 twips, which is 18 pixels at 96 dpi. `normalize_nonclientmetrics` raises it to 2 + `tmHeight` of the caption font if that is larger. The caption font is the default GUI font at −11 pixels, bold. Wine's Tahoma Bold (`fonts/tahomabd.sfd`, `OS2WinAscent` 2049 + `OS2WinDescent` 423 over 2048 units) is 13 pixels tall there, so 18 stands. neww has no font engine. This answer rests on Wine's own font file and on the substitution of `MS Shell Dlg` with Tahoma. `tests/test_neww_caption_height.py`.
- `USER.66` `GetDC` is Wine `user.exe16/window.c` `GetDC16` (`66 pascal -ret16 GetDC(word) GetDC16`, pop 2), `HDC_16` of user32 `GetDC`. `hwnd` 0 is the screen. Wine takes a free DCE from its cache, so each `GetDC` with no `ReleaseDC` is a new DC. Wine's HDC is a win32u GDI handle. neww numbers its own from `0x1004` by 4, which is never a selector or a moveable handle. That number is neww's, not Wine's. A window's DC stops, because neww has no windows. `TB80RTM` asks for the screen DC. `tests/test_neww_getdc.py`.
- `GDI.80` `GetDeviceCaps` is Wine `gdi.exe16/gdi.c` `GetDeviceCaps16` (`gdi.exe16.spec` `80 pascal -ret16 GetDeviceCaps(word s_word) GetDeviceCaps16`, pop 4), which turns a `NUMCOLORS` of −1 into 2048. neww has no display driver. Wine's null user driver gets nulldrv's DC functions, so the screen DC is `win32u/driver.c` `nulldrv_GetDeviceCaps` over Wine's default display: `modes[2]`, 1024×768 at 32 bits and 60 Hz, at 96 dpi. `HORZSIZE` and `VERTSIZE` are `mapping.c` `muldiv`, rounded to nearest: 271 and 203 mm. A cap with no case is 0. A DC neww did not make stops. This is GDI's first row in neww. `TB80RTM` asks `BITSPIXEL`. `tests/test_neww_getdevicecaps.py`.
- `USER.68` `ReleaseDC` is Wine `user.exe16/window.c` `ReleaseDC16` (`68 pascal -ret16 ReleaseDC(word word) ReleaseDC16`, pop 4). `win32u/dce.c` `release_dc` returns 1 for a DC in use, without looking at `hwnd`, and gives a cache DC back. A DC not in use returns 0. `GetDC(0)` then takes the first released DC of the desktop window in `dce_list`, which `list_add_head` keeps newest first, before it makes a new one. So a `GetDC`/`ReleaseDC` pair hands out the same HDC each time. `tests/test_neww_releasedc.py`.
- `KERNEL.36` `GetCurrentTask` is Wine `task.c` `WIN16_GetCurrentTask` (`36 pascal GetCurrentTask() WIN16_GetCurrentTask`, pop 0, long): the current task in `AX`, `hFirstTask` in `DX`. The task handle is `TASK_Create`'s `GlobalAlloc16(GMEM_FIXED, sizeof(TDB))`, 0x200 bytes. Wine links the exe's task after the main task at the same priority, so `TASK_LinkTask` puts it first, and both words are the same handle. neww makes the block but not the TDB in it, so a guest read stops. Wine's PSP is that TDB's `pdb` at +0x100, and neww's PSP stays a block of its own. `SetWindowsHookEx`'s `hTask` stop still says neww has no task handle. Comparing `hTask` with this handle is a later PR. `tests/test_neww_getcurrenttask.py`.
- `KERNEL.18` `GlobalLock` is Wine `global.c` `WIN16_GlobalLock16` (`18 pascal GlobalLock(word) WIN16_GlobalLock16`, pop 2, long). `K32WOWGlobalLock16` returns `MAKESEGPTR(sel, 0)`, so `DX` is the selector and `AX` is 0, and `WIN16_GlobalLock16` puts the selector in `CX` too. −1 is `CURRENT_DS`. An invalid handle gives selector 0. A valid one counts a lock, the same count `LockSegment` keeps. neww used to return the handle in `AX` with `DX` 0, a null far pointer, and `TB80RTM` stopped in `FatalAppExit("unexpected heap error")`. `tests/test_neww_globallock.py`.
- `KERNEL.20` `GlobalSize` is Wine `global.c` `GlobalSize16` (`20 pascal GlobalSize(word) GlobalSize16`, pop 2, long): the arena's size in `DX:AX`. Handle 0 and an invalid handle are 0. `GET_ARENA_PTR` finds the arena from the selector, so a moveable block's handle and selector both work. A `GlobalAlloc` block is its `GLOBAL_Alloc` size, rounded up to 32 bytes, and over 64K that is the whole block, not its first selector's segment. `tests/test_neww_globalsize.py`.
- A moveable block's handle loads as its selector. Wine's moveable handle is the selector − 1, the same LDT entry at RPL 2, so Win16 code can put the handle in `DS` or `ES`. `TB80LNL` calls `LocalInit(handle, ...)` and then loads the handle into `DS`. neww's handle used to be the selector − 1 in the GDT. - One CPU runs one task at a time, as the Win16 lock allows. A switch happens only where Wine gives up the lock: `GetMessage`, `WaitMessage` and `PeekMessage` with nothing to return, `Yield`, `DirectedYield` and `WaitEvent`. The machine saves the task's registers at the gate and loads the next task's through a tail at `0xFFF0:20h`, which loads `SS:SP`, `DS` and `ES` by instruction and jumps to `CS:IP`. A gate's `OUT` cannot move `CS:IP` itself, so the stub's `retf` goes to the tail. A task waiting for a message resumes at its gate stub and the call runs again; one that yielded resumes at the stub's `retf` with its answer. The next task is the first, in creation order after the current one, that can run. When none can, the clock moves to the earliest timer of a waiting task. When there is none, every task waits for input and the run stops. `GetCurrentTask`'s `DX` is `hFirstTask`, the newest task. `IsTask`, `PostEvent`, `WaitEvent` (`TRUE` after a wait, as `WaitEvent16` answers) and `GetModuleUsage` know every task.
